## What is a widget?

A widget is the fundamental unit in the Acme placeholder platform. Every widget belongs to exactly one workspace and has a stable identifier, a display color, and an optional metadata bag. Widgets are cheap to create and expensive to lose, which is why the imaginary Acme team recommends tagging them liberally.

Widgets compose into sprockets, and sprockets combine into gadgets. This mirrors how many real products layer primitives into higher-level abstractions, but every specific detail on this page is fabricated.

## Widgets, sprockets, and gadgets

| Concept  | Cardinality        | Owns          | Typical use                    |
| -------- | ------------------ | ------------- | ------------------------------ |
| Widget   | One per record     | Metadata      | Smallest building block        |
| Sprocket | Many widgets       | Configuration | Groups related widgets         |
| Gadget   | Many sprockets     | Permissions   | Ships to end users             |

<Note>Cardinalities above are illustrative. A real product would enforce these with schema constraints.</Note>

## Lifecycle

Every widget moves through four states. The transitions are one-way except for `archived → active`, which requires an admin action.

<Steps>
  <Step title="draft">Created but not yet visible to collaborators.</Step>
  <Step title="active">Available to sprockets and gadgets in the same workspace.</Step>
  <Step title="paused">Temporarily hidden without deleting attachments.</Step>
  <Step title="archived">Retained for audit but excluded from queries by default.</Step>
</Steps>

## Migration example

The imaginary v2 client renamed `label` to `name` and dropped the `legacy_id` field. Here is what the diff looks like in a consumer:

```ts migrate.ts lines
const widget = await acme.widgets.create({
  label: "Sprocket",           // [!code --]
  name: "Sprocket",            // [!code ++]
  legacy_id: "old_123",        // [!code --]
  color: "emerald",
});
```

<Tip>When you migrate, run both clients side by side for one release and diff the responses.</Tip>
